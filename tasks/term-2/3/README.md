# Lab 3 — Load Testing Report

## Как запустить

### Требования
- Java 21+

### Компиляция и запуск
```bash
cd tasks/term-2/3
javac *.java
java Main
```

Программа сама запускает сервер в 4 конфигурациях, отправляет запросы и выводит таблицу результатов.

## Описание эксперимента

Тестируется HTTP-сервер с двумя маршрутами:

- **Request-1 `/request1`** — принимает JSON `{"id": N, "name": "hello"}`, сохраняет имя в файл `data_N.txt`, читает файл обратно, возвращает JSON `{"status": "ok", "saved": "hello"}`.
- **Request-2 `/request2`** — принимает JSON `{"value": 42}`, считает квадрат числа в памяти, возвращает JSON `{"result": 1764}`.

Каждый маршрут проверяется в 4 комбинациях:

| Вариант | Потоки | JSON-парсер |
|---------|--------|-------------|
| Virtual + Own parser | Virtual threads (Java 21) | Собственный `JsonParser` (lab-1) |
| Virtual + Gson | Virtual threads (Java 21) | `GsonParser` |
| Classic + Own parser | FixedThreadPool (10 потоков) | Собственный `JsonParser` (lab-1) |
| Classic + Gson | FixedThreadPool (10 потоков) | `GsonParser` |

|-----------|---------------------|----------------|----------------------|----------------|

## Выводы

- **Request-1** медленнее Request-2 во всех вариантах — он обращается к диску (запись + чтение файла).
- **Virtual threads** при первом запуске немного медленнее — JVM разогревается. После прогрева разница минимальна.
- **Classic + FixedThreadPool** чуть быстрее на простых вычислениях (Request-2), потому что нет накладных расходов на создание виртуальных потоков.
- **Own parser vs Gson** — на маленьких JSON (~30 байт) разница незначительная. На больших объёмах данных настоящий Gson будет быстрее.
