
## Настройка и запуск

### Требования
- Java 21+
- Apache JMeter 5.6.3

### Запуск сервера
Запускайте сервер из командной строки в директории с проектом, используя необходимые флаги:

| Конфигурация | Команда запуска |
|---|---|
| **Classic + GSON** | `java -cp "bin;lib/*" lab3.ServerRunner` |
| **Classic + Own Parser** | `java -cp "bin;lib/*" lab3.ServerRunner --own-parser` |
| **Virtual + GSON** | `java -cp "bin;lib/*" lab3.ServerRunner --virtual` |
| **Virtual + Own Parser** | `java -cp "bin;lib/*" lab3.ServerRunner --virtual --own-parser` |

*Сервер будет запущен на `http://localhost:8080`.*

### Запуск JMeter
1. Открыть `C:\JMeter\bin\jmeter.bat`.
2. Загрузить файл `jmeter/load_test.jmx`.
3. Перед запуском теста в **HTTP Request** снять галочку "Use KeepAlive".
4. Нажать **Start**.
5. Результаты будут в **Summary Report**.

## Описание эксперимента
Эксперимент измеряет пропускную способность (Throughput) и среднее время отклика (Average Response Time) HTTP-сервера при разных стратегиях многопоточности и методах парсинга JSON.

**Тестируемые эндпоинты:**
- `POST /store`: I/O-bound операция (запись JSON в файл, чтение последней записи).
- `POST /calculate`: CPU-bound операция (парсинг JSON, вычисление суммы полей).

## Заключение и выводы
Стабильность системы (уровень ошибок 0,00%) была достигнута после настройки сетевых параметров.

**Ключевые выводы:**
1. **Стабильность:** Отключение режима `Keep-Alive` в JMeter и увеличение `Ramp-up period` до 60 секунд полностью устранили ошибки `BindException` и `SocketException`, вызванные исчерпанием эфемерных портов ОС.
2. **Производительность:** На текущем объеме нагрузки (10 000 запросов) различия между использованием стандартной библиотеки GSON и собственной реализацией парсера, а также между классическими и виртуальными потоками, являются минимальными (в пределах 1-3 мс).
3. **Тип нагрузки:** Операции записи в файл (`/store`) ожидаемо показывают чуть более высокое время отклика, чем операции вычисления в памяти (`/calculate`), что подтверждает влияние I/O-операций на общую задержку системы.
