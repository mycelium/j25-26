# Load testing report

## Настройка и запуск

### Требования
- Java 21+ (для поддержки виртуальных потоков), сборка и тестирование проводились на java 25
- Gradle 9.4.1
- Библиотека gson версии 2.10.1


### Сборка и запуск
1. Открыть проект в корневой папке `3`.
2. Компиляция сервера и нагрузочного теста:
```bash
gradle clean fatJar
```
3. Запуск сервера:
```bash
java -jar app/build/libs/app-all.jar 8081 virtual own 200
```
сначала передается порт, на котором будет запущен сервер; потом тип многопоточности `[classic | 
virtual]`; после тип парсера json `[own | gson]` - реализация из `lib/lab1-parser.jar` или 
библиотечная из gson соответственно.
4. Запуск нагрузочного теста:
```bash
java -cp app/build/libs/app-all.jar loadtest.LoadTest http://localhost 8081
```
порт необходимо указать тот же, на каком порте был запущен сервер.

## Описание эксперимента
Всего сравнивается 4 конфигурации:
1. Виртуальные потоки + парсер из lab-1
2. Виртуальные потоки + парсер из библиотеки gson
3. Классические потоки + парсер из lab-1
4. Классические потоки + парсер из библиотеки gson

Для каждой конфигурации измеряется среднее время обработки двух типов запросов:

- Request‑1 (I/O‑bound):
Сервер принимает JSON `{"data":"<строка>"}` (размер ~512 байт), парсит его, сохраняет строку во временный уникальный файл на диске, затем читает этот файл обратно, удаляет его и возвращает JSON `{"stored":"...","retrieved":"..."}`.

- Request‑2 (memory‑bound):
Сервер принимает JSON `{"a":10000}`, парсит его, вычисляет сумму квадратов чисел от 1 до a (10000) с кэшированием результата в `ConcurrentHashMap`, и возвращает JSON `{"result":...}`.
