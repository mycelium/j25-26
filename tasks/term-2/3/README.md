### Компиляция

Из корневой директории проекта (папка 3) выполнить команду:
javac -cp "lib/*:src" src/ServerForTest.java src/LoadTest.java


### Запуск сервера
Запуск из директории проекта с соответствующим флагом:


| Конфигурация | Команда запуска |
|---|---|
| **Classic + GSON** | `java -cp "lib/*:src" ServerForTest --gson` |
| **Classic + Own Parser** | `java -cp "lib/*:src" ServerForTest` |
| **Virtual + GSON** | `java -cp "lib/*:src" ServerForTest --virtual --gson` |
| **Virtual + Own Parser** | `java -cp "lib/*:src" ServerForTest --virtual` |
---
Сервер будет запущен на http://localhost:8080

После запуска сервера в другом окне терминала (из папки 3):
# /store (Request‑1)
java -cp "lib/*:src" LoadTest store
# /compute (Request‑2)
java -cp "lib/*:src" LoadTest compute

Тест отправляет 1000 запросов (50 потоков × 20 запросов) и выводит среднее время ответа, общую длительность и пропускную способность.


## Описание эксперимента
Эксперимент измеряет среднее время отклика (Average Response Time) HTTP-сервера при разных стратегиях многопоточности и методах парсинга JSON.

POST /store: I/O-bound операция — принимает JSON {"id":12345}, парсит, записывает id в файл storage.txt, читает весь файл и возвращает JSON с полями status, id, stored.
POST /compute: CPU-bound + память — принимает JSON {"n":10}, парсит, вычисляет факториал n, сохраняет результат в ConcurrentHashMap и возвращает JSON с полями result, key, storage_size.

**Сравниваются четыре конфигурации:**
- Virtual Threads + собственный JSON парсер (lab-1)
- Virtual Threads + Gson
- Classic Thread Pool + собственный JSON парсер (lab-1)
- Classic Thread Pool + Gson

## Заключение и выводы

**Ключевые выводы:**
1. **Стабильность:** Все тесты прошли без ошибок, сервер выдержал нагрузку 1000 запросов. 
2. **I/O vs CPU:** Операции записи/чтения файла (/store) ожидаемо медленнее вычислений в памяти (/compute).
3. **Собственный парсер vs Gson:** Собственный парсер показал лучшую производительность, чем Gson, во всех конфигурациях (разница 1–5 мс в пользу собственного парсера).
4. **Влияние типа потоков:** В данной нагрузке классические потоки отработали быстрее виртуальных. Это может быть связано с небольшим количеством одновременных I/O операций и накладными расходами на планирование виртуальных потоков.5.
