# Отчет по нагрузочному тестированию

## 1. Конфигурация и запуск

### Зависимости

- Java 21+
- Подключенные `.jar` файлы в папке `lib`: `gson-2.10.1.jar`, `http.jar`, `jsonengine.jar`.

### Сборка и запуск

1. Открыть проект в корневой папке.
2. В исходном коде файла `src/ServerApp.java` настроить параметры тетсирования (`ENABLE_VIRTUAL_THREADS`, `ENABLE_GSON`, `MAX_WORKERS`)
3. В командной строке перейти в корень проекта
4. Компиляция сервера и клиента для проведения тестирования
   ```bash
   javac -cp "lib/*" src/ServerApp.java src/BenchmarkRunner.java
   ```
5. Запуск сервера
   ```bash
   java -cp "lib/*;src" ServerApp
   ```
6. После запуска сервера запустить клиента
   ```bash
   java -cp "lib/*;src" BenchmarkRunner
   ```


## 2. Эксперимент

Тестируется пропускная способность сервера и скорость обработки двух типов HTTP-запросов:

- Request 1 (I/O Bound): Сервер принимает JSON объект, парсит его, создает на диске уникальный временный файл, записывает туда данные, читает их обратно, удаляет файл и возвращает JSON-ответ клиенту. Имитация жесткой работы с файловой системой.
- Request 2 (CPU Bound): Сервер принимает JSON с числами, парсит их, производит математические операции (сложение) в оперативной памяти и возвращает JSON с результатом.

Производится 4 прогона тестов с комбинациями параметров потоков (классические 16 потоков против виртуальных) и JSON процессоров (написанный в первой лабораторной работе против Google Gson).

## 3. Аппаратное обеспечение

- **Операционная система**: Windows 11 Pro
- **Процессор**: Intel Core i9 9900k
- **JVM**: Java 21
- **Оперативная память**: 64 Гб ddr4
- **Дисковое пространство**: SSD

## 4. Параметры эксперимента

- **Количество параллельных клиентов (CONCURRENCY)**: 50
- **Общее количество запросов на каждый роут (REQUESTS)**: 100
- **Размер классического пула потоков сервера (THREAD_POOL_SIZE)**: 16
- **Тело запроса Request‑1**: `{"data":"Hello IO Testing"}`
- **Тело запроса Request‑2**: `{"a":2048,"b":4096}`
