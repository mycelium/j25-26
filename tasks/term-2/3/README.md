## Настройка и запуск

### Требования
- Java 21+
- Apache JMeter 5.6.3

### Компиляция проекта
В корневой директории проекта (папка `3`) выполнить команду:

```bash
javac -d bin -cp "lib/*" src/lab3/ServerRunner.java
```

### Запуск сервера
Запуск из директории проекта с соответствующим флагом:

| Конфигурация | Команда запуска |
|---|---|
| **Classic + GSON** | `java -cp "bin;lib/*" lab3.ServerRunner` |
| **Classic + Own Parser** | `java -cp "bin;lib/*" lab3.ServerRunner --own-parser` |
| **Virtual + GSON** | `java -cp "bin;lib/*" lab3.ServerRunner --virtual` |
| **Virtual + Own Parser** | `java -cp "bin;lib/*" lab3.ServerRunner --virtual --own-parser` |

*Сервер будет запущен на `http://localhost:8080`.*

*Команды в таблице предназначены для Windows (Git Bash). Для Linux или macOS, разделитель в кавычках необходимо изменить с точки с запятой на двоеточие: `"bin:lib/*"`.*


### Запуск JMeter
1. Открыть `C:\JMeter\bin\jmeter.bat`.
2. Загрузить файл `jmeter/test_load.jmx`.
3. Перед запуском теста убедиться что галочка "Use KeepAlive" в **HTTP Request** снята.
4. Нажать **Start**.
5. Результаты будут в **Summary Report**.

### Альтернативный запуск тестов через консоль 


Во втором окне терминала (при запущенном сервере) выполните команду (из папки `3`):
```bash
/c/JMeter/apache-jmeter-5.6.3/bin/jmeter.bat -n -t jmeter/test_load.jmx -l jmeter/results_bash.jtl
```

### Примечание по настройке ОС
Для корректной работы при высокой нагрузке (50 потоков) необходимо расширить диапазон эфемерных портов Windows. Выполнить в PowerShell от имени администратора:
```powershell
netsh int ipv4 set dynamicport tcp start=1024 num=64511
```
После выполнения команды перезагрузить компьютер.

## Описание эксперимента
Эксперимент измеряет пропускную способность (Throughput) и среднее время отклика (Average Response Time) HTTP-сервера при разных стратегиях многопоточности и методах парсинга JSON.

**Тестируемые эндпоинты:**
- `POST /store`: I/O-bound операция — принимает JSON, парсит, записывает в файл `data/storage.json`, читает и возвращает последнюю запись.
- `POST /calculate`: CPU-bound операция — принимает JSON, парсит, вычисляет сумму числовых полей, возвращает результат в виде JSON.

**Сравниваются четыре конфигурации:**
- Virtual Threads + собственный JSON парсер (lab-1)
- Virtual Threads + Gson
- Classic Thread Pool + собственный JSON парсер (lab-1)
- Classic Thread Pool + Gson

**Примечание:** JMeter и HTTP сервер запускались на одной машине, что могло повлиять на результаты по сравнению с запуском на разных машинах.

## Заключение и выводы

**Ключевые выводы:**
1. **Стабильность:** Расширение диапазона эфемерных портов ОС командой `netsh` и отключение режима `Keep-Alive` в JMeter устранят ошибки `BindException` и `SocketException`, вызванные исчерпанием портов при высокой нагрузке.
2. **I/O vs CPU:** Операции записи в файл (`/store`) показывают более высокое время отклика по сравнению с вычислениями в памяти (`/calculate`), что подтверждает влияние дисковых операций на задержку.
3. **Собственный парсер vs Gson:** Собственный парсер показал сопоставимые или лучшие результаты по сравнению с Gson на простых плоских JSON объектах — разница в пределах 1-5 мс.
4. **Виртуальные vs классические потоки:** На данном объёме нагрузки существенной разницы не наблюдается — оба варианта справляются с 50 параллельными соединениями. Виртуальные потоки показывают преимущество при большом количестве одновременных I/O-операций.
