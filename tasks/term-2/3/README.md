# Load Testing

### Требования
- Java 21+ (нужна для virtual threads)
- Библиотеки в папке `lib/`: `gson-2.10.1.jar`, `http-server.jar`, `json-parser.jar`

## 1. Сборка и запуск

### Перейдите в папку проекта

```
cd tasks\term-2\3
```

### Скомпилируйте:
```
javac -d out -cp "lib/*" src/main/java/com/loadtest/*.java
```

### Запуск тестов
```
# Mac / Linux
java -cp "lib/*:." com.benchmark.TestRunner

# Windows
java -cp "lib/*;." com.benchmark.TestRunner
```

### Запуск с параметрами (запросы, concurrency)
```
java -cp "lib/*:." com.benchmark.TestRunner 1000 20
```

## 2. Описание эксперимента

### Тестируемые endpoint'ы
- **POST `/file`** (Request-1) —  Парсинг JSON → запись поля data в файл → чтение файла → возврат JSON. **I/O-bound**.
- **POST `/compute`** (Request-2) — Парсинг JSON → вычисление суммы и среднего массива values → возврат JSON. **CPU-bound**, без I/O.

### Конфигурации сервера (4 варианта)

| № | Модель потоков | JSON библиотека |
|---|----------------|------------------|
| 1 | Virtual threads | Собственный парсер (из Лабы 1) |
| 2 | Virtual threads | Gson 2.10.1 |
| 3 | Classic pool (50 потоков) | Собственный парсер |
| 4 | Classic pool (50 потоков) | Gson 2.10.1 |

### Как проходит тест

1. Прогрев: 200 запросов (не учитываются)
2. Основной тест: 1000 запросов с 20 параллельными клиентами
3. Измеряется среднее время на запрос (мс)
4. Сервер перезапускается между конфигурациями

## 6. Анализ результатов
### 6.1 I/O-нагрузка (/file) — запись/чтение файла

| Конфигурация | Время (мс) | Место |
|---|---|---|
| Classic + собственный парсер | 16.752 |  1  |
| Classic + GSON | 17.319 |  2  |
| Virtual + GSON | 20.870 |  3  |
| Virtual + собственный парсер | 25.982 | 4  |

### Выводы:

- Classic потоки на 35-55% быстрее virtual для файловых операций
- Лучший результат: Classic + собственный парсер (16.75 мс)
- Худший результат: Virtual + собственный парсер (25.98 мс)

### Почему classic быстрее на MacBook Air 2014?

- 2-ядерный процессор — virtual потоки создают дополнительные накладные расходы на переключение
- Файловый I/O на SSD не блокирует потоки надолго, поэтому преимущества virtual нивелируются
- Старый MacBook (2014) не оптимизирован под virtual threads

### 6.2 CPU-нагрузка (/compute) — вычисления

| Конфигурация | Время (мс) | Место |
|---|---|---|
| Classic + собственный парсер | 11.159 | 🟢 1 место |
| Virtual + GSON | 12.743 | 🟢 2 место |
| Virtual + собственный парсер | 13.466 | 🟢 3 место |
| Classic + GSON | 14.155 | 4 место |

### Выводы:

- **Classic + собственный парсер снова лучший (11.16 мс)**
- Virtual потоки показали себя достойно (отставание всего 14–21%)
- Gson на classic потоках оказался медленнее всех — неожиданный результат

### 6.3 Сравнение парсеров (среднее по всем конфигурациям)

| Парсер | Среднее время (file + compute) |
|---|---|
| Собственный (classic) | 13.96 мс (лучший) |
| Собственный (virtual) | 19.72 мс |
| Gson (classic) | 15.74 мс |
| Gson (virtual) | 16.81 мс |

**Вывод:** Собственный парсер на classic потоках — абсолютный лидер.

## 7. Заключение
- Все 4 конфигурации успешно протестированы на MacBook Air 2014
- Classic потоки + собственный парсер — лучшая конфигурация для обоих типов нагрузки
- Собственный парсер быстрее Gson во всех сценариях
- Virtual threads не дали преимущества на старом 2-ядерном процессоре
- Фреймворк нагрузочного тестирования работает корректно
