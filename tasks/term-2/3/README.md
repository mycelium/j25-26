# Task 3/Load testing report

## 1. Настройка и запуск

### Требования

- Java 21+
- Gradle 8+

### Сборка и запуск

1. Перейти в папку с проектом
```bash
cd path/to/folder/tasks/term-2/3/l3
```

2. Собрать проект:
   ```bash
   .\gradlew.bat build
   ```

3. Запустить сервер с нужной конфигурацией:
   ```bash
   .\gradlew.bat run --args="<threadMode> <jsonMode> <port> <threads>"
   ```
   - `threadMode` — `virtual` или `classic` 
   - `jsonMode` — `own` (парсер из лаб 1) или `gson`
   - `port` — порт сервера (по умолчанию `8080`)
   - `threads` — размер классического пула (только для `classic`, по умолчанию `8`)

4. Во время работы сервера запустить тест:
   ```bash
   ./gradlew runLoadTest --args="<endpoint> <totalRequests> <concurrency>"
   ```
   - `endpoint` — `store` (Request-1) или `compute` (Request-2)
   - `totalRequests` — общее количество запросов (по умолчанию `1000`)
   - `concurrency` — количество параллельных клиентов (по умолчанию `50`)

---

## 2. Описание эксперимента

Эксперимент измеряет среднее время обработки двух типов HTTP-запросов:

- **Request-1**: сервер принимает JSON `{"value":"..."}`, парсит его, сохраняет строку в SQLite-базу данных `storage.db`, читает обратно из БД и возвращает JSON `{"stored":"..."}`.
- **Request-2**: сервер принимает JSON `{"numbers":[1,2,...,100]}`, парсит его, вычисляет сумму элементов массива в памяти и возвращает JSON `{"sum":...}`.

Сравниваются четыре конфигурации:

- Собственный JSON-парсер + виртуальные потоки
- Собственный JSON-парсер + классический пул потоков
- Gson + виртуальные потоки
- Gson + классический пул потоков

## 4. Параметры эксперимента

- **Количество параллельных клиентов (concurrency)**: 50
- **Общее количество запросов на каждый endpoint (totalRequests)**: 1000
- **Размер классического пула потоков сервера (threads)**: 8
- **Тело запроса Request-1**: `{"value":"load-test-sample-data"}` (~36 байт)
- **Тело запроса Request-2**: `{"numbers":[1,2,...,100]}` (~370 байт)
