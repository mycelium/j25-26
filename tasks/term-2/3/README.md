# Load Testing Report

## 1. Настройка и запуск

### Требования

- Java 21+ (обязательно для поддержки виртуальных потоков)
- Gradle 8+ (или встроенный `gradlew` wrapper)

### Сборка и запуск

1. Открыть терминал в корневой папке проекта.
2. Проект настроен на автоматический прогон всех 4 конфигураций. Ручное редактирование флагов не требуется.
3. Сборка и запуск одной командой:

```bash
./gradlew run
```

> При запуске класс `Main` последовательно стартует сервер, проводит нагрузочный тест, собирает метрики и останавливает сервер для каждой из 4 комбинаций (Virtual/Classic × OwnParser/Gson).

---

## 2. Описание эксперимента

Эксперимент измеряет среднее время обработки двух типов HTTP-запросов:

- **Request-1** — сервер принимает JSON `{"key":"...","value":"..."}`, парсит его, сохраняет пару в файловую базу данных SQLite (`test.db`), затем считывает её обратно и возвращает JSON `{"retrieved":"..."}`. Имитирует **I/O-bound** нагрузку.
- **Request-2** — сервер принимает JSON `{"number":...}`, парсит его, выполняет вычисления в памяти (`n * n + n * 31`) и возвращает JSON `{"result":...}`. Имитирует **CPU-bound** нагрузку.

Сравниваются четыре конфигурации:

| # | Конфигурация |
|---|---|
| 1 | Собственный JSON-парсер (`jsonlib`) + виртуальные потоки |
| 2 | Собственный JSON-парсер + классический пул потоков |
| 3 | Gson + виртуальные потоки |
| 4 | Gson + классический пул потоков |

## 4. Параметры эксперимента

| Параметр | Значение |
|---|---|
| Количество параллельных клиентов (`CONCURRENCY`) | 50 |
| Количество запросов на один поток | 100 |
| Общее количество запросов на конфигурацию | 5 000 |
| Размер классического пула потоков (`THREAD_POOL_SIZE`) | 200 |

|--------|---------------------:|---------------:|---------------------:|---------------:|

| Request-2 | 3.94 ms | 3.34 ms | 3.33 ms | 2.65 ms |
